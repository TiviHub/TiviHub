# Security Policy

## Reporting a vulnerability

Please do not report exploitable vulnerabilities in public issues, discussions, or pull requests.

Use GitHub's **Report a vulnerability** option in the repository's **Security** tab to send a private vulnerability report. The maintainer should enable **Private vulnerability reporting** in the repository's security settings. The maintainer will acknowledge the report and coordinate investigation and disclosure there.

If private vulnerability reporting is unavailable, contact the repository maintainer through a private contact method listed on their GitHub profile. Do not include exploit details or sensitive data in a public report.

## Scope

Reports are welcome for vulnerabilities in TiviHub's application code and handling of user or provider credentials. Issues in third-party playlist providers or services should be reported to those providers.

Please include the affected version or commit, impact, and concise reproduction steps. Do not include real playlist URLs, provider credentials, personal data, or signing-key material.

## Supported versions

Until the first public beta, only the latest source on `main` is supported. Once public releases begin, security fixes will target the latest supported release.
